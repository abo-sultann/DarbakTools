# Darbak Production Release Gate

هذا المستند هو بوابة الإصدار الرسمية لجميع تطبيقات دربك على شاشة السيارة Android 7.1 / API 25 بدقة 1024×600.

## المبدأ

نجاح Build لا يعني أن النسخة Production جاهزة. لا يعتمد أي APK رسمي قبل إغلاق جميع البوابات أدناه.

## 1. Code QA

- ينجح CI على الفرع المستهدف.
- تنجح Unit Tests المتاحة.
- ينجح Android Lint.
- ينجح assembleDebug أو المسار الاختباري المكافئ.
- لا تُستخدم نسخة Debug كنسخة توزيع رسمية.

## 2. Stable Signing

- لكل تطبيق مفتاح Production ثابت لا يتغير بين الإصدارات.
- يمنع إنشاء Release رسمي إذا لم يتوفر مفتاح التوقيع الخارجي.
- لا تحفظ keystore أو كلمات المرور داخل GitHub أو داخل الكود.
- أي تطبيق انتقل من Debug/توقيع سابق إلى مفتاح Production جديد يحتاج تثبيت Production baseline يدوي مرة واحدة، ثم تصبح جميع التحديثات التالية بنفس الشهادة.

## 3. Update Verification

قبل فتح Android Package Installer يجب أن يتحقق التطبيق من:

1. HTTPS فقط.
2. versionCode أعلى من النسخة المثبتة.
3. packageName مطابق للتطبيق الحالي.
4. minSdk / توافق النظام يسمح بالتثبيت على Android 7.1.
5. حجم الملف عند توفره.
6. SHA-256 مطابق للـmanifest.
7. شهادة توقيع APK مطابقة لشهادة النسخة المثبتة بعد اعتماد Production baseline.

عند فشل أي فحص يحذف APK ولا يفتح شاشة التثبيت.

## 4. Distribution

- GitHub الخاص هو مصدر الكود وليس قناة تنزيل التطبيق على الشاشة.
- قناة التوزيع الرسمية تكون عبر ملفات Google Drive عامة للقراءة فقط.
- manifest وAPK يستخدمان IDs ثابتة قدر الإمكان، ويتم استبدال المحتوى في نفس الملفات عند التحديثات القادمة.
- لا يعلن manifest إصدارًا أعلى قبل رفع APK Production الموقّع والتحقق من SHA-256 والحجم.

## 5. Physical Head Unit QA

لا تتحول الحالة إلى Production إلا بعد تجربة حقيقية على شاشة Allwinner T3:

- تثبيت/ترقية فوق النسخة الحالية.
- تشغيل أول مرة بدون Crash أو Safe Mode غير مقصود.
- إعادة تشغيل الشاشة والتطبيق.
- اختبار الصلاحيات والتخزين والإنترنت/GPS حسب التطبيق.
- اختبار اللمس والقراءة على 1024×600.
- مراقبة الذاكرة والاستقرار مع الاستخدام الطويل قدر الإمكان.
- اختبار «البحث عن تحديث» من داخل التطبيق ثم تثبيت نسخة أحدث تجريبية موقعة بنفس الشهادة.

## 6. Production Status

الحالات المسموح بها في `registry/apps.json`:

- `reference-implementation`
- `hardening-in-validation`
- `blocked-by-signing-baseline`
- `ready-for-device-qa`
- `production-approved`

لا تستخدم `production-approved` إلا بعد نجاح Physical Head Unit QA.

## الهوية الرسمية

جميع التطبيقات تعتمد هوية:

**دربك — تصميم وتطوير — أبوسلطان**

وتلتزم بـ Darbak Settings UI V1 وصفحة «حول» الموحدة عند تحديث واجهات الإعدادات.
